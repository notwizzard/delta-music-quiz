# Музыкальная своя игра

Две программы, которые вместе дают готовую викторину «угадай мелодию» в формате
Своей игры.

**Студия** — сборка игры в браузере: загрузить музыку, наделать из неё заготовок
(ускорить, замедлить, задом наперёд, выше, ниже, наложить треки друг на друга),
разложить их по доске и вписать ответы.

**Готовая игра** — один файл `.html` со звуком внутри. Копируется на любой
ноутбук и открывается двойным кликом. Ни установки, ни интернета, ни сервера.

> **Важно про раздачу.** Готовую игру можно просто отправить кому угодно одним
> файлом — она откроется двойным кликом, ничего ставить не надо. А вот студию
> архивом не раздашь: ей нужны Python и ffmpeg, её ставят один раз на тот
> компьютер, где игры готовятся.

---

## Что нужно поставить и зачем

Студию ставят **один раз** на тот компьютер, где будут готовиться игры. Дальше
она открывается в браузере как обычный сайт.

| Программа | Зачем нужна | Обязательна? |
|---|---|---|
| **Homebrew** (только Mac) | магазин программ для Терминала, через него ставится остальное | да, на Mac |
| **Git** | скачивает проект и потом обновляет его одной командой | да |
| **Python** 3.10 или новее | на нём написана студия | да |
| **ffmpeg** | читает и пишет весь звук | да |
| **rubberband** | качественнее замедляет и меняет высоту | нет, но желательно |

Без `rubberband` всё работает, просто ускорение и сдвиг высоты звучат немного
грязнее — с лёгким металлическим призвуком.

# Установка на Mac

## Шаг 1. Открыть Терминал

Нажми <kbd>⌘</kbd> + <kbd>пробел</kbd>, набери `Терминал` и нажми Enter.
Откроется чёрное окно — в него мы будем вставлять команды.

Дальше правило простое: копируешь команду, вставляешь в это окно, жмёшь Enter,
**дожидаешься**, пока снова появится строка с приглашением, и только потом
переходишь к следующей.

## Шаг 2. Поставить Homebrew

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

Установщик попросит пароль от компьютера. Пароль **не отображается** при вводе —
ни точек, ни звёздочек. Это нормально, просто набери его вслепую и нажми Enter.

Установка занимает несколько минут. В самом конце Homebrew напечатает пару
команд под заголовком `Next steps`. Их нужно выполнить — иначе Терминал не будет
видеть `brew`. На современных маках это:

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
```

Проверяем, что получилось:

```bash
brew --version
```

Если в ответ напечаталась версия — всё хорошо. Если `command not found`, закрой
Терминал, открой заново и проверь ещё раз.

## Шаг 3. Поставить остальные программы

```bash
brew install git python ffmpeg rubberband
```

Это самый долгий шаг, до десяти минут. Можно заварить чай.

## Шаг 4. Скачать проект

```bash
cd ~/Documents
git clone https://github.com/notwizzard/delta-music-quiz.git
cd delta-music-quiz
```

Проект окажется в папке `Документы/delta-music-quiz`.

## Шаг 5. Установить студию

```bash
./install.sh
```

Скрипт проверит, что всё на месте, и доставит недостающее. В конце напишет
`Готово`.

## Шаг 6. Запустить

```bash
./start.sh
```

Браузер откроется сам на странице студии. В окне Терминала будет написано, где
лежит рабочая папка. **Это окно нельзя закрывать, пока идёт работа** — студия
живёт в нём. Чтобы завершить, нажми в нём <kbd>Ctrl</kbd> + <kbd>C</kbd>.

Дальше студию можно открывать двойным кликом по файлу **«Запустить
студию.command»** в папке проекта — Терминал больше не понадобится.

# Установка на Windows

## Шаг 1. Открыть PowerShell

Нажми <kbd>Win</kbd>, набери `PowerShell` и открой **Windows PowerShell**.
Откроется синее окно — в него мы будем вставлять команды.

## Шаг 2. Поставить Git, Python и ffmpeg

```powershell
winget install -e --id Git.Git
```

```powershell
winget install -e --id Python.Python.3.12
```

```powershell
winget install -e --id Gyan.FFmpeg
```

Каждую команду выполняй отдельно и дожидайся окончания. Если Windows спросит
разрешение — соглашайся.

**Обязательно закрой окно PowerShell и открой заново.** Windows показывает
новые программы только в новых окнах, и без этого следующий шаг выдаст ошибку.

Проверяем в новом окне:

```powershell
git --version
python --version
ffmpeg -version
```

Все три должны напечатать версии. `rubberband` на Windows ставить не нужно —
без него всё работает.

## Шаг 3. Скачать проект

```powershell
cd ~\Documents
git clone https://github.com/notwizzard/delta-music-quiz.git
cd delta-music-quiz
```

## Шаг 4. Установить студию

```powershell
python -m venv .venv
```

```powershell
.venv\Scripts\pip install -e .
```

Второй шаг займёт пару минут — скачиваются библиотеки для работы со звуком.

## Шаг 5. Запустить

```powershell
.venv\Scripts\dmq studio
```

Браузер откроется сам. **Окно PowerShell закрывать нельзя, пока идёт работа.**
Чтобы завершить, нажми в нём <kbd>Ctrl</kbd> + <kbd>C</kbd>.

Каждый следующий раз достаточно двух команд:

```powershell
cd ~\Documents\delta-music-quiz
```

```powershell
.venv\Scripts\dmq studio
```

## Как обновиться до свежей версии

Когда в проекте появится что-то новое:

```bash
cd ~/Documents/delta-music-quiz
git pull
```

На Windows путь пишется как `cd ~\Documents\delta-music-quiz`.

Твоя музыка, заготовки и собранные игры лежат **отдельно** от проекта — в папке
`Документы/Музыкальная игра`. Обновление их не трогает.

## Если что-то пошло не так

**`command not found` или `не является внутренней или внешней командой`.**
Закрой окно Терминала или PowerShell и открой заново. В девяти случаях из
десяти это помогает: новые программы видны только в новых окнах.

**На Windows команда `python` открывает Microsoft Store.** Это подстава от
Windows: вместо Python там пустышка. Попробуй писать `py` вместо `python`, а
если не поможет — поставь Python заново командой из шага 2.

**«Порт 4321 занят другой программой».** Студия уже запущена в другом окне.
Найди её по адресу `http://127.0.0.1:4321/` или закрой то окно.

**Студия не открылась в браузере сама.** Скопируй адрес из окна Терминала
(`http://127.0.0.1:4321/`) и вставь в браузер вручную.

**Домашняя папка называется не `Documents`.** На русской системе она может быть
`Документы`. Тогда используй в командах именно это название.

## Что можно потрогать прямо сейчас

В папке `demo/` лежит собранная игра со звуками-пищалками. Открой
`demo/demo.html` двойным кликом — это ровно то, что получается на выходе,
только с синтетическим звуком вместо музыки.

## Как собрать игру

Студия ведёт по трём шагам.

**1. Музыка.** Перетащи файлы в окно. Каждый трек разбирается: определяются
темп, тональность и самое энергичное место — обычно припев, оттуда и режется
фрагмент. Дальше кнопками делаются заготовки. Чтобы наложить треки друг на
друга, отметь галочками 2–4 штуки и нажми «Наложить».

Про диапазон стоит знать одну вещь: **сначала вырезается кусок оригинала, и
только потом к нему применяется преобразование**. «Задом наперёд, начало 0:55,
длина 40» — это отрезок 0:55…1:35, проигранный назад, а не вся песня наоборот
с последующей обрезкой. Длина тоже считается по оригиналу, поэтому ускорение
делает заготовку короче запрошенного: 40 секунд при ускорении в 1.5 раза дадут
26 секунд звучания, а замедление вдвое — 80.

Если хвоста не хватает, кусок просто укоротится. Начало за пределами трека
студия отклонит с понятным сообщением.

**2. Доска.** Темы идут строками, клетки — по возрастанию цены. Нажми на
клетку, выбери звук, впиши ответ. Звуком ответа по умолчанию подставляется
оригинал того же трека — то есть когда ответ показан, зал слышит, как песня
звучит на самом деле.

К вопросу можно приложить картинку — обложку, кадр, что угодно. Для неё
выбирается момент появления: **вместе с ответом** (по умолчанию, чтобы не
выдать разгадку раньше времени) или **сразу в вопросе**, если картинка сама
работает подсказкой. Ведущий всегда видит картинку у себя и подпись, когда её
увидит зал.

**3. Готовая игра.** Студия проверит, всё ли заполнено, и соберёт один файл.

## Как вести игру

1. Открой скачанный файл двойным кликом — это пульт ведущего.
2. Подключи проектор или телевизор **вторым экраном**, не зеркалом.
3. Нажми «Открыть экран для зала», перетащи новое окно на большой экран и
   разверни его на весь экран.
4. На своём ноутбуке остаётся пульт: там видны ответы и начисляются баллы.

Пока звук играет, на экране зала фоном оживает узор — калейдоскоп, который
дышит в такт музыке. Он разбирает звук вживую, поэтому честно реагирует на
любое преобразование: замедленный трек шевелится медленно, а не пытается
попасть в несуществующий ритм. На паузе узор замирает, и это само по себе
видно залу. Выключается кнопкой «Визуализация» в пульте, выбор запоминается.

Звук работает как обычный проигрыватель: играй, ставь на паузу и перематывай
в любую точку — тяни ползунок мышью или прыгай по пять секунд.

Управление с клавиатуры: <kbd>пробел</kbd> — играть и пауза, <kbd>←</kbd>
<kbd>→</kbd> — перемотка на 5 секунд, <kbd>1</kbd>…<kbd>9</kbd> — кнопка
команды, <kbd>Esc</kbd> — закрыть вопрос.

Счёт сохраняется сам, так что случайно закрытая вкладка не обнуляет игру.

## Что умеет обработка

| Преобразование | Что слышно |
|---|---|
| Ускорение в 1.25 / 1.5 / 2 раза | быстрее, но голоса не пищат |
| Замедление в 1.5 / 2 / 4 раза | медленнее, но голоса не гудят |
| Задом наперёд | трек в обратную сторону |
| Выше на 3 / 5 / 7 полутонов | другая тональность, скорость прежняя |
| Ниже на 3 / 5 / 7 полутонов | то же вниз |
| Наложение 2–4 треков | звучат одновременно и в один бит |

Наложение — самое интересное. Треки анализируются, приводятся к общему темпу,
по желанию подтягиваются в одну тональность и выравниваются по первой сильной
доле такта, так что удары у всех совпадают.

## Командная строка

Студия закрывает почти всё, но обработку можно гонять и напрямую:

```bash
dmq presets                              список преобразований
dmq analyze track.mp3                    темп, тональность, сильные доли
dmq transform track.mp3 --all -o out/    все преобразования одного трека
dmq batch tracks/ -o out/ --clip 40      то же по всей папке
dmq mashup a.mp3 b.mp3 --bars 8          наложение
dmq studio                               студия
dmq export                               сборка игры из рабочей папки
```

## Как это устроено

```
src/dmq/
  audio.py       чтение, запись, громкость
  analysis.py    темп, сетка долей, сильные доли, тональность
  transforms.py  скорость, высота, реверс
  mashup.py      наложение с попаданием в бит
  presets.py     готовые преобразования с подписями
  library.py     фонотека: треки и заготовки
  pack.py        модель игры: темы, клетки, ответы, картинки
  render.py      изготовление заготовок
  exporter.py    сборка самодостаточного html
  studio/        локальное веб-приложение студии
  web/game/      шаблон готовой игры
```

Рабочая папка по умолчанию — `~/Documents/Музыкальная игра`. Внутри: `sources/`
с оригиналами, `renders/` с заготовками, `images/` с картинками, `exports/`
с готовыми играми, `library.json` и `pack.json` с описанием.

### Два решения, которые стоит объяснить

**Почему визуализация разбирает звук вживую, а не по заранее посчитанным
долям.** Половина наших преобразований ломает ритм: замедление вчетверо даёт
тридцать ударов в минуту, реверс превращает удар в затухающий хвост наоборот.
Заготовленная сетка долей на таком материале врала бы, а `AnalyserNode`
показывает ровно то, что слышит зал. Заодно это ничего не меняет в формате
пака — старые игры пересобираются как есть.

Вся визуализация необязательна: если Web Audio почему-то не заводится, узора
просто нет, а звук играет как раньше. Холст лежит отдельным слоем под
содержимым зала, иначе перерисовка обрывала бы анимацию на каждом действии
ведущего.

**Почему картинки пережимаются при упаковке.** Они едут внутрь файла игры, и
одно фото с телефона на 4000 пикселей раздуло бы его сильнее, чем весь звук.
Поэтому картинки ужимаются до 1400 пикселей: прозрачные уходят в PNG, остальные
в JPEG — он в разы легче, а на проекторе разницы не видно. WebP был бы лучше
обоих, но его поддержка есть не в каждой сборке ffmpeg.

**Почему готовая игра — один файл со звуком внутри.** Игру ведут с чужого
ноутбука, часто без интернета и без права что-то устанавливать. Папка с файлами
разваливается при пересылке, локальный сервер требует терминала, веб-версия
требует сети. Один html работает везде. Платим размером: звук внутри в base64,
поэтому перед упаковкой он пережимается в моно 96 kbps — для угадайки этого
хватает с запасом.

**Почему второе окно, а не два открытых файла.** Файлы, открытые с диска,
браузер считает разными источниками, поэтому `BroadcastChannel`, `localStorage`
и `postMessage` между ними не работают. А окно, созданное через
`window.open("")`, наследует источник родителя — и пульт может писать прямо в
его DOM. Это единственный способ синхронизировать два экрана без сервера.

## Тесты

```bash
.venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest tests/ -q
```

Проверки идут на синтетических треках с заранее известными темпом и
тональностью — на настоящей музыке не с чем сравнивать. Отдельно проверяется
главное свойство наложения: удары всех слоёв сходятся с точностью лучше 5%
доли.
